## 10. 無料部分だけで、あなたが今日できること

ここまでの数字から、お金をかけずに今日できることを並べます。

**① 自分の分野の有料記事のスキ中央値を数える**

note の検索で自分の分野を開き、有料記事を20本ほど見て、スキの数を書き出してください。
中央値が**2以下**なら、上の表の「恋愛」「生成AI」と同じ場所にいます。
分野を変えるか、**買う人がいる隣の分野に寄せる**かを考える材料になります。

**② いまの価格を見直す**

500円や980円で出しているなら、**部数が同じでも売上が数倍変わります**。
下げる理由は、このデータの中には見つかりませんでした。

**③ 無料部分の文字数を数える**

いまの無料部分が2,000字を切っているなら、売れている例の**6分の1以下**です。
「はじめに」で終わっていないか、読んだ人が何か1つ持ち帰れるかを見てください。

**④ 記事の1行目を読み返す**

自分の状況から始まっていたら、読者の困りごとに書き換えます。
私はこれを72本やってから気づきました。

**⑤ 本数を増やす前に、1本を厚くする**

私は72本書いて、確認できた3本は0部でした。記事1本の人が740部売っています。
**本数は、少なくとも私の場合、効いていませんでした。**

## 11. 数えるための最小のコードを、ここに置きます

「自分の分野を数えてください」と書いておいて、やり方を有料にするのは不親切なので、
**動く最小版をここに出します。** コピーして実行するだけです。

Pythonの標準ライブラリだけで動きます。インストールも、APIキーも、お金も要りません。

```python
import json, urllib.request, urllib.parse, statistics

UA = {'User-Agent': 'Mozilla/5.0'}
q = '復縁'                      # ← ここを自分の分野の言葉に変える

rows = []
for page in range(5):           # 20件 × 5ページ = 100件
    url = (f'https://note.com/api/v3/searches?context=note'
           f'&q={urllib.parse.quote(q)}&size=20&start={page*20}&sort=popular')
    with urllib.request.urlopen(urllib.request.Request(url, headers=UA)) as r:
        notes = json.load(r)['data']['notes']['contents']
    if not notes:
        break
    rows += [(x.get('price') or 0, x.get('like_count') or 0) for x in notes]

paid   = [likes for price, likes in rows if price]
prices = [price for price, likes in rows if price]

print(f'{q}： 全{len(rows)}件 / 有料{len(paid)}件（{len(paid)/len(rows)*100:.1f}%）')
print(f'  有料記事のスキ 中央値 {statistics.median(paid):.0f}')
print(f'  有料記事の価格 中央値 {statistics.median(prices):.0f}円')
```

実際に動かすと、こう出ます。

```
復縁： 全100件 / 有料43件（43.0%）
  有料記事のスキ 中央値 48
  有料記事の価格 中央値 980円

Claude Code： 全100件 / 有料22件（22.0%）
  有料記事のスキ 中央値 106
  有料記事の価格 中央値 1980円
```

**1つ注意があります。** この最小版は「人気順」の100件しか見ません。
人気順は上澄みなので、**数字は本編の表より高めに出ます。**
本編の表は、人気順と新着順の両方を各分野10ページずつ取って出したものです。
この差を知らずに「うちの分野はスキ中央値48もある」と読むと、判断を誤ります。

有料部分には、**本編の表を作ったスクリプトそのもの**を置いてあります。
30分野を自動で回し、書き手のフォロワーも取り、「○部売れた」の記述も拾う版です。

## 12. おまけ：私が「測っていたつもり」で消していたもの

数える話をしているので、自分の失敗をひとつ書きます。**数えた記録が、消えていた話**です。

Threadsの自動投稿で、1投稿ごとの表示回数をデータベースに記録していました。
毎日21時に投稿し、毎晩その数字を取り直す。そういう仕組みを自分で組みました。

10月16日、その表を開いたら、**10件しか入っていませんでした。** 8月から毎日投稿しているのにです。

投稿そのものは止まっていませんでした。Threads本体を確認すると、1日も欠けていません。
**消えていたのは記録のほうでした。**

原因は自分のコードでした。1つの表を2つの用途に使っていたんです。

1. 「この周回でどの原稿を使ったか」の置き場（同じ文面を続けて出さないため）
2. 表示回数の記録

原稿を一周すると、1のために置き場を空にします。そのとき、**2の記録も一緒に消えていました。**

幸い、Threadsは後からでも表示回数を取れるので、48件分を取り直せました。
この記事の「61日で3,657回表示」は、その復旧後の数字です。

ついでに、もう1つ見つかりました。同じ文面が**10月10日と10月16日の6日間で2回**出ていました。
一周したあと、無作為に選び直していたためです。

**「測っている」と「測れている」は別でした。**
数字を根拠に判断するなら、その数字がどこに、いつまで残るかを先に決めておく必要があります。
私はそれをせずに2か月走って、9月分を失いました。

## 13. 同じ物差しを、自分の30本に当てた

この記事を出す前に、ゼロ円開発ログの公開中30本を、同じやり方で数えました（2026年10月24日）。

| 見たこと | 結果 |
|---|---|
| note検索（人気順）の上位100件に、自分の記事が入った語 | **17語のうち0語** |
| 題名の文字数 | **32〜64字**（30本すべて） |
| 有料3本の無料部分 | **993〜1,289字** |
| 全PVのうち、有料記事が占める割合 | **10.6%**（246のうち26） |
| 1本あたりのスキ（中央値） | **1** |

調べた17語は「Claude Code」「Threads」「自動投稿」「note 収益化」など、私の記事に関係する語です。
**どの語でも、100位までに1本も出てきませんでした。**

一方で、届きそうな語も見つかりました。
人気順の1ページ目（20件）に入っている記事のうち、**いちばん少ないスキの数**を並べます。

| 語 | 1ページ目に入る最低のスキ | 1ページ目の有料記事 |
|---|---|---|
| Zenn | **0** | 2本 |
| 自動投稿 | **4** | 4本 |
| AI自動化 | **6** | 2本 |
| Cloudflare | **10** | 3本 |
| Claude Code | 39 | 9本 |
| Threads | 42 | 10本 |
| note 収益化 | 114 | 6本 |

「Claude Code」で1ページ目に入るには、スキが39要ります。私の記事のスキは、いちばん多い1本で12です。
「自動投稿」なら4で届きます。

**だから、狙う語をスキの数で選び直します。** 私の題名には、30本のうち28本に「Claude Code」が入っていました。
いちばん混んでいる語に、いちばん弱い記事で挑んでいたことになります。

あなたも同じ表を作れます。上の最小のコードで、`rows` を人気順に並べたときの20番目までの最小のスキを見てください。
それが、その語で1ページ目に入るための目安です。
