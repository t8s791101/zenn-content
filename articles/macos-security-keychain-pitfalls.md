パスワードを置く小さなCLIを書いていて、macOSの `security` コマンドで3回つまずきました。**どれもエラーを出さずに壊れます。** 返り値は0で、保存できたように見えます。

## 1. 値を引数で渡すとプロセス一覧に出る

まずこれを避けたくて、標準入力から渡す方法を探しました。

```bash
# 見えてしまう
security add-generic-password -a myacct -s mysvc -U -w 'ひみつ'
```

`-w` に値を**書かずに**渡すと、security は対話的に聞いてきます。このとき標準入力から読みます。ただし**「入力」と「確認の再入力」で2回読む**ので、同じ値を2回流す必要があります。

```bash
printf '%s\n%s\n' "$v" "$v" | security add-generic-password -a myacct -s mysvc -U -w
```

`-w -` と書くと、**ハイフンがそのまま値として保存されます。** 最初これで「取り出すと `-` が返る」状態になりました。返り値は0です。

## 2. 非ASCIIを入れると、16進で返ってくる

```bash
printf 'ぱすわーど\nぱすわーど\n' | security add-generic-password -a jp -s mysvc -U -w
security find-generic-password -a jp -s mysvc -w
# => e381b1e38199e3828fe383bce381a9
```

保存自体は成功しています。`find -w` の出力が、ASCIIで表せない場合に16進文字列へ切り替わります。**切り替わったことを示す目印はありません。**

「16進に見えたらデコードする」で判定すると、`e381b1...` という値そのものを保存したときに壊れます。

## 3. 128文字で黙って切られる

```
入力 120字 → 取得 120字  一致
入力 127字 → 取得 127字  一致
入力 128字 → 取得 128字  一致
入力 129字 → 取得 128字  切られた
入力 160字 → 取得 128字  切られた
```

境界はちょうど128です。**超えた分は警告なしに消えます。** APIトークンのような長いものは入りません。

## どう直したか

**値は必ず base64 にしてから入れる**ことにしました。これで1と2が同時に消えます。

- base64はASCIIなので、16進への切り替えが起きない
- base64は1行なので、改行を含む値も通る

長さだけは解決しないので、**入る大きさを超えたらエラーで止める**ようにしました。base64は4/3倍になるので、実際に入るのは93バイトまでです。

```python
MAX_STORED = 128
PREFIX = "b64:"
MAX_BYTES = (MAX_STORED - len(PREFIX)) // 4 * 3   # 93
```

## いちばん効いた対策は、読み戻すこと

```python
# 保存したあと、必ず取り出して一致を確かめる
if self.get(name) != value:
    sys.exit("保存した値が読み戻せませんでした")
```

上の3つは**全部これで見つかりました。** `security` の返り値は3回とも0でしたし、ドキュメントを読んでも出てきません。

書き込み系のAPIを包むときは、**成功の判定を相手の返り値に任せない**。書いた後に読んで突き合わせる。4行で済みます。
