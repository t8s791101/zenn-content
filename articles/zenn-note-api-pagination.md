自分のブログの数字を毎日記録する仕組みを作っています。**同じ間違いを4回しました。** 全部「ページが分かれているAPIを、1ページ目だけ読んだ」です。

## 4回の内訳

| 回 | どのAPI | 1ページの件数 | 起きたこと |
|---|---|---|---|
| 1 | 記事一覧 | 6 | 記事数を少なく数えた |
| 2 | 記事一覧（別の用途） | 6 | 同上 |
| 3 | PV統計 | 12 | 17本中12本しか記録されず、**PVの少ない記事が丸ごと抜けた** |
| 4 | 別サービスの統計 | **5** | 7本中5本しか返らず、古い2本が消えたように見えた |

4回目は、3回目の反省を書いた後に踏みました。**同じ罠だと分かっていても、別のサービスだと気づけません。**

## なぜ気づきにくいか

エラーが出ないからです。返ってくるJSONは正常で、配列にもデータが入っています。**足りないことだけが分かりません。**

さらに悪いことに、多くのAPIは**並び順がPV降順**です。落ちるのは必ず「数字が小さい記事」。合計への影響が小さいので、合計値を見ていても異常に見えません。

3回目のときは、合計PVが183と出ていて、実際は189でした。6の差では気づけません。

## 実際に効いた対策

### 1. 必ず最後まで読むループにする

```javascript
let page = 1, all = [], guard = 0;
while (guard++ < 10) {                 // 無限ループ防止
  const d = await get(page);
  const items = d.items || [];
  all = all.concat(items);
  if (items.length === 0) break;       // または d.last_page
  page++;
}
```

打ち切り条件は2種類あります。`last_page` のようなフラグがあるならそれを使い、無ければ**空配列が返るまで**回します。`guard` は必ず入れます。1回、APIが同じページを返し続けて止まらなくなりました。

### 2. 件数を別の情報源と突き合わせる

これが一番効きました。

```
統計APIが返した件数（22） vs 公開記事数（22） → 一致
```

公開記事数は認証の要らない別のAPIから取れます。**同じAPIの中で完結させない**のがポイントです。1ページ目だけ読んでいると、この比較で必ず引っかかります。

一致しないこと自体は異常とは限りません（0ビューの記事は統計に出ないことがある）。**大事なのは、差が出たときに黙って通さないこと**です。差を数字で報告に出すようにしました。

### 3. 「取れなかった」と「0だった」を分ける

抜けた記事を0として記録すると、**あとから区別できなくなります**。記録しない、または「取得できず」として残す。これを混ぜた日のデータは、後から見て何も言えなくなりました。

## 学んだこと

ページングは、**失敗が静かな**タイプのバグです。落ちない、エラーも出ない、値もそれらしい。だから「動いているように見える」状態が続きます。

対策も、ループを直すことより**件数を突き合わせる仕組みを外側に置く**ほうが効きました。ループは書き直すたびに間違えますが、突き合わせは1回作れば全部のAPIに効きます。
