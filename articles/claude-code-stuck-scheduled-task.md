Claude Code の定期実行（スケジュールタスク）を毎朝2本動かしています。2026年9月25日から27日までの3日間、**その2本とも1度も動きませんでした。** エラーは出ていません。通知もありません。

原因は「前日の実行が終わっていなかった」ことでした。

## 気づいたきっかけ

毎日の実行結果を、タスク自身に1行ずつデータベースへ書かせています。**開始で1行、終了で1行**です。

```
INSERT INTO daily_actions (done_on, action, result, ok)
VALUES ('2026-09-25', '日次タスク開始', '開始', 1);
```

9月27日にこのテーブルを見たら、25日・26日・27日の**開始行そのものが無い**。終了行が無いなら「途中で止まった」ですが、開始行が無いのは「そもそも始まっていない」です。

この2行を書かせていなかったら、「動いたけど何もしなかった日」と区別できませんでした。

## スリープを疑って、違った

まずMacが寝ていたと考えました。定期実行はローカルで動くので、Macが寝ていれば動きません。

確かめたのは2つです。

```bash
uptime
# 23:16  up 4 days, 12:53
```

再起動していません。そして、動くはずだった時刻の前後にファイルが更新されているかを見ました。

```bash
find ~/Library/Logs -newermt "2026-09-25 09:00" ! -newermt "2026-09-25 11:00"
# 09:56 のログファイルが見つかった
```

**9時56分にMacは起きていました。** タスクの予定時刻は9時10分と10時1分です。スリープではありません。

## 本当の原因

実行履歴を見たら、こうなっていました。

| タスク | 開始 | 最後の活動 | 状態 |
|---|---|---|---|
| A（9:10） | 9月24日 09:10 | 開始の46秒後 | **実行中** |
| B（10:01） | 9月24日 10:01 | 開始の4秒後 | **実行中** |

どちらも**開始直後に止まり、そのまま46時間「実行中」のまま**でした。そして新しい実行は1度も作られていません。実行回数のカウンタも、24日から増えていませんでした。

止まっている実行を停止したら、両方とも「成功」に変わり、翌朝から通常どおり動きました。

## 前の実行が次を塞ぐ、という失敗の形

これは「動かなくなった」ではなく「**動けなくなった**」です。同じ形の失敗は、cron以外でもよく踏みます。

- ロックファイルを消さずに異常終了したバッチ
- 前のジョブが残っていて起動しないキューワーカー
- 応答しないまま接続を掴んでいるコネクションプール

共通しているのは、**失敗の通知が出ないこと**です。前の実行は「失敗」ではなく「まだ実行中」なので、エラーとして扱われません。監視していたのが「失敗の数」だけだと、ゼロのまま何日も過ぎます。

## 入れた対策

日次タスクの手順に、1行足しました。

> 実行履歴を見て、**前日の実行が「実行中」のまま残っていないか確かめる**。残っていたら報告する。

もうひとつは、最初から入れていた開始行・終了行です。**開始だけあって終了が無い日＝途中で止まった日**、**開始すら無い日＝起動していない日**。この2つを分けておかないと、今回の切り分けはできませんでした。

「動かなかった」を検知する仕組みは、動いた側に書かせるのが確実です。動かなかったものは、自分では何も言いません。
